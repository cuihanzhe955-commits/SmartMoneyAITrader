### 1.2 v1.0 Stable 必须达到的产品能力

1. **真实交易：** 连接受支持交易所，展示真实行情/余额/持仓；规则与 AI 两种引擎均可经过独立风控进入真实下单链；具备成交、撤单、止盈止损、对账、恢复和日志。
2. **多交易所：** Gate / OKX / Binance 采用“任一时刻单主平台运行”架构，账户、订单、余额、持仓及风控不跨平台串用；每个平台独立验收，不把一家平台成功概括成全部成功。
3. **现有能力不回退：** 保留 OKX 现货、规则策略、已有会话配置、深色工作台、数据库和 Phase 3 风险预算。
4. **AI 自治但受控：** AI 是军师与交易员，生成可解释的结构化交易提案；允许 `SKIP`；永远不能越过独立风控、订单状态机与实际执行权限。
5. **AI Memory：** 从**模拟交易第一次运行**开始记录经验，结算后自动复盘，保存可追溯长期记忆，后续预测按需检索；切换模型后记忆仍在。
6. **两个挑战分开：** 原有“24小时翻倍”挑战保持纯规则决策；另建“100轮 AI 预测”挑战，提供只读预测、影子交易、模拟成交、结算和成绩复盘。
7. **Polymarket 预测研究：** 替换原 Gate 事件平台定位，优先建立 Polymarket 市场发现、行情、预测、模拟及结算适配；具体接口与账户准入仍待验证，不将模拟成交标为实盘。Gate / OKX / Binance 的现货规划保留。
8. **OpenClaw + 消息：** 飞书机器人（通过 OpenClaw）、Telegram 可在 Smart Money UI 中添加、更换、测试、启停，通知服务故障不影响交易。
9. **日日新迁移：** OpenClaw 从本地 Ollama / llama.cpp 主模型迁移到商汤日日新免费模型候选 `sensenova-6.8-flash-lite`；原有 Gateway、通知通道和本地模型保留回滚能力。
10. **最少调试：** 高频操作、密钥更换、模型选择、平台切换、风险参数、通知及记忆管理通过 UI 完成；高级设置折叠，错误给出可操作的诊断，不要求普通用户编辑 `.env` 或运行命令。
11. **真实功能优先：** 不做只有前端的空按钮；每个用户可见功能必须有真实后端状态、数据链路及失败处理。
12. **GitHub 安全：** 未经用户明确授权，不创建公开仓库、不发布/推送主工程、不覆盖远程分支；旧 `smart-money-mobile` 不视为 Windows 主工程。

### 1.3 需要在开发中明确化的冲突

- **“所有功能可用”与“外部 API 未验证”**：真实现货交易是 Stable 硬性目标；Polymarket 事件预测的只读/模拟功能也要真实可运行，但事件合约专用实盘如未验证，不能冒称可用。最终发布能力清单必须按交易所和产品分别标记。
- **“参数尽量不硬拦截”与“防错交易”**：推荐范围超限时只提醒；交易所最小金额、数量精度、余额、幂等、产品能力、过期信号等执行不变量必须硬校验。
- **“AI 自主成长”与“实盘可控”**：可自动积累记忆、提出新假设、改进模拟预测；不得未经明确授权自增杠杆、提高风险、修改实盘策略参数。
- **“最少调试”与“高可靠”**：通过向导、自动健康检查、诊断与一键恢复降低用户负担，不减少工程测试和真实资金验收。

## 2. 推荐系统架构与核心边界

```text
React/TypeScript UI：交易工作台 | AI 中心 | 两种挑战 | Brain | 设置中心
                    |
             Python API / Application Services
                    |
   MarketScheduler ---> Snapshot/Indicators ---> Rule Engine / AI Worker
                    |                            |
      独立保护性通道（止损/查单/对账）      有时效的结构化决策
                    |                            |
                    +------> 独立风控 + 幂等订单意图 <----+
                                      |
             ----------------------------------------
             |                       |               |
      Spot Live Executor       Paper Executor    Event Research
             |                       |               |
       Gate/OKX/Binance      模拟账本/成本      预测/模拟/结算
             |                       |               |
             +-------------- 持久化事件账本 ------------+
                                      |
                      Brain/Memory、回放与绩效分析
                                      |
                   异步通知队列 ---> OpenClaw ---> 飞书/Telegram
```

**严格解耦：** AI 推理、长期记忆写入、OpenClaw 机器人发送、图表渲染均不得成为止损、订单查询、风控及数据对账的同步依赖。**模型分工：** OpenClaw 对话/通知主模型与 Smart Money 交易决策模型独立配置，可以相同，也可以不同。

### 2.1 最小接口契约（以现有源码命名为准）

- `MarketSnapshot`：平台、产品、交易对/事件 ID、来源时间、接收时间、版本、有效期、数据质量。
- `Decision`：唯一 ID、snapshot ID、模型/规则版本、配置版本、方向、概率、预期收益、`SKIP`/参与、截止时间、证据。
- `RiskVerdict`：风险校验结果、阻止原因、允许订单预算、可用余额、交易成本和精度解释。
- `OrderIntent`：平台+账户+产品+唯一幂等键；关联源决策、请求时间、目标数量和风险预算。
- `OrderState`：待发送、待确认、已接受、部分成交、已成交、已取消、已拒绝、未知状态、已对账。
- `LearningRecord`：会话/轮次、输入快照、预测、结果、校准情况、观察/假设/已验证/失效标签、来源证据。
- `NotificationEvent`：事件 ID、事件类型、通道、目标、重试次数、发送状态、模拟/真实标记。

## 4. Phase 4 可靠性修复：优先级最高

### 4.1 AI 调度解耦

- 审计 `ai/provider.py`、`terminal/runtime.py` 以及实际调用链；采用现有项目适配的异步任务或隔离工作器、有界队列、超时和取消机制。
- 行情扫描、保护性退出、账户对账、交易所流同步和订单状态更新不等待模型；通知与记忆写入亦为独立队列。
- 队列满、模型 429、网络失败或模型卡住时，丢弃过期决策并记录原因；按照用户已设置的策略切换规则引擎、暂停新仓或等待人工，**不得自动加大风险**。

### 4.2 决策失效与风控

- 交易动作前重检快照年龄、市场数据质量、平台/账户/产品、模型和配置版本、事件窗口、余额及订单限制。
- 超时 AI 返回的提案一律不能直接执行；`SKIP` 必须完整入账并在 UI 可追踪。
- 所有真实订单先独立风控、再创建幂等订单意图；失去时效即停止新交易，不影响既有持仓保护。

### 4.3 止损与订单生命线

- 区分**本地循环止损**与**交易所已确认的保护单**；不允许将本地监控冒充交易所托管。
- 订单提交超时 -> `UNKNOWN` -> 查询交易所订单/成交 -> 明确状态后处理；禁止直接再次提交形成重复订单。
- 正确处理部分成交、部分撤单、手续费、实际均价、重启后恢复、余额差异、切换交易所时遗留未完订单。
- 实盘启动前，自动检查 API 可达性、授权、余额、市场规则、保护措施、事件账本及数据一致性；出现阻断项不得静默跳过。

## 5. 真实交易交付范围及验收

- v1.0 **不是只能模拟**。Gate、OKX、Binance 的通用现货是目标交易所产品，采用单平台执行，不要求同时在三家实盘下单。
- 实际支持范围由官方 API、账户权限及经过执行器测试的能力注册表决定，逐所报告：行情/余额/下单/撤单/查单/部分成交/精度/费率/风险/重启恢复。
- 真实交易验收须按最小合规订单规格，在用户明确授权后执行受控的小金额真实订单，核对交易所回执、成交、余额、费用、取消/退出及保护状态。未完成真实测试则不能宣称该平台已经实盘验收。
- 停止程序不等于交易所仓位平仓；必须向用户明确告知未完订单/持仓，保护任务不能在静默退出时丢失。
- 推荐值超出区间时警示但允许保存；交易所硬性交易规则、无法验证的订单状态、非法数据及执行权限必须强制校验。

## 7. Polymarket 与事件预测技术准备

- **已核对通用 Gate API v4：** 提供现货、杠杆、合约等产品的一般行情和认证交易能力，包含 REST 与 WebSocket；这是通用能力结论，不是事件合约专用自动交易的确认。
- 事件预测模块独立于现货执行器，区分平台事件ID、市场ID、结果Token标识、标的、事件起止、参考基准、报价与官方结算来源。优先研究加密资产短周期涨跌市场；币种及5分钟等周期必须通过实际市场发现确认，不预设一定存在。
- 事件结果不能以普通现货 K 线涨跌替代官方结算；报价缺失时只允许明确标注的假设性回测；不允许产生看似真实的模拟成交订单号。
- 二元事件单张预期净收益按 `EV = 校准后胜出概率 × 胜出兑付额 + (1 - 概率) × 失败兑付额 - 实际买入价 - 单张估计成本` 计算；结算资产、兑付规则、费用、滑点及可成交报价以具体市场为准，不套用 Gate 的 USDT 假设。
- Gate 事件合约接入状态及统一接口设计，以文末 2026-11-04 修订为准。

## 8. Smart Money Brain：模拟开始学习（v1.0 必交付）

### 8.1 真实闭环

`开始模拟 → 快照及预测持久化 → 模拟订单/成本 → 可信结算 → AI 反思 → 假设/经验入库 → 后续按场景检索 → 独立评估`。

- 本地长期记忆优先复用现有数据库，不贸然新建第二套基础设施。可以逻辑划分 `identity / preferences / observations / hypotheses / lessons / reflections / snapshots / exports`。
- 每条经验含生成时间、来源决策与快照、模型版本、适用市场/周期、证据状态、版本和失效条件。
- 支持多模型共享（GPT/Claude/Gemini/DeepSeek/日日新等），但隔离不同交易会话、平台、模拟与实盘数据来源；用户可在 UI 搜索、纠错、暂停写入、导出、恢复。
- 只从已确认且可追溯的结算结果生成“验证后经验”；单次盈利、错误数据、未结算轮次不能直接认定策略有效。
- 对照“有记忆/无记忆”模型，在相同历史条件下按时间前向评价 Brier Score、Log Loss、净收益、最大回撤、SKIP 比率；严格避免未来数据泄漏和测试集反复调参。
- 长期记忆写入失败不阻塞真实订单或保护性任务；AI 经验只能提出建议，不能未经授权修改实盘风控。

### 8.2 用户界面

AI Brain 提供：开启/暂停模拟学习、自动复盘、在后续决策中引用经验、已记录轮次、最近经验、验证状态、纠错/导出和“这一建议引用了哪段记忆”。高级记忆清理及向量索引等功能折叠。

## 11. 两种挑战、回放与绩效

- **原 24 小时挑战：** 持续保留纯规则策略执行，不暗中注入 AI 作为交易决策；AI 可以仅做配置辅助或事后分析。目标为实验指标，不是收益承诺。
- **100轮 AI 预测：** 每轮可预测/跳过/模拟成交/等待结算/完成；记录时间、标的、模型、方向、成本、收益、资金、正确率、交易胜率、最长连胜/连败及最大回撤。
- 已预测次数、已参与次数、已结算次数严格分开；`SKIP` 不生成虚假成交，未结算轮次不纳入已实现收益；同一结算幂等入账。
- 两种挑战都支持中断恢复、历史回放、成绩分析与消息播报；模拟账本与真实余额严格隔离。

## 15. 2026-11-04 修订：事件市场平台可用性与统一接口

本节为接续项目决策，覆盖前文冲突表述。仅修改设计计划，不代表代码、连接器或实盘验收已完成。

### 15.1 Gate 当前结论

- 已实际验证 API V4 私有签名及 Wallet 汇总只读查询返回 HTTP 200，响应存在 `event_contract` 账户分类。此前旧密钥 Wallet 查询返回缺少权限。
- 尚未确认普通账户可访问的五分钟涨跌事件合约历史订单、成交、退款、结算、行情及下单官方专用接口。当前按“未验证可接入／暂不可执行”处理，不能写成绝对没有 API，也不能因资产分类存在而宣称可交易。
- Gate DexBuilder 提供企业合作事件合约能力，不足以证明普通 API V4 Key 能读取 Gate App 内同一产品账户。
- 未取得历史事件账本 API 数据；407条及相关人工核算仍待独立 API 核验。不以普通永续、期权或现货账本替代事件合约内部账本。
- 本轮原始密钥、私人余额、账户身份及流水不写入计划或公开仓库。

### 15.2 先定义可替换的事件市场适配层

- 先形成接口契约、标准数据模型和能力注册表；不因 Gate 阻断而停止通用预测及模拟架构设计。本次用户已明确授权将事件研究平台替换为 Polymarket：其只读行情、市场发现、模拟及结算适配纳入既定事件研究实施路径；真实执行适配保留接口设计，启用需独立准入和验收。Kalshi、富途仍在未来需求池，其他冻结范围不扩张。
- `EventMarketAdapter` 读能力分别定义：`discover_markets`、`get_market_rules`、`subscribe_quotes`、`get_snapshot`、`list_orders`、`list_fills`、`list_ledger`、`get_positions`、`get_settlement`。
- 未来写能力 `submit_order`、`cancel_order` 单独隔离；接口定义不是开启实盘的授权。本次账本审计仍严格只读。
