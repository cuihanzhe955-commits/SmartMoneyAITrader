### 1.2 v1.0 Stable 必须达到的产品能力

1. **真实交易：** 连接受支持交易所，展示真实行情/余额/持仓；规则与 AI 两种引擎均可经过独立风控进入真实下单链；具备成交、撤单、止盈止损、对账、恢复和日志。
2. **多交易所：** Gate / OKX / Binance 采用“任一时刻单主平台运行”架构，账户、订单、余额、持仓及风控不跨平台串用；每个平台独立验收，不把一家平台成功概括成全部成功。
3. **现有能力不回退：** 保留 OKX 现货、规则策略、已有会话配置、深色工作台、数据库和 Phase 3 风险预算。
4. **AI 自治但受控：** AI 是军师与交易员，生成可解释的结构化交易提案；允许 `SKIP`；永远不能越过独立风控、订单状态机与实际执行权限。
5. **AI Memory：** 从**模拟交易第一次运行**开始记录经验，结算后自动复盘，保存可追溯长期记忆，后续预测按需检索；切换模型后记忆仍在。
6. **挑战功能边界：** “24小时翻倍挑战”已获准移除。先审计路由、配置、调度、数据库、测试、报告和打包依赖，再只删除挑战专属代码与入口；保留历史报告/记录。G1 自动预测挑战及其历史证据必须保留，不得连带删除策略实验室、通用回测、通知或 Brain。
7. **Polymarket 预测研究：** 替换原 Gate 事件平台定位，优先建立 Polymarket 市场发现、行情、预测、模拟及结算适配；具体接口与账户准入仍待验证，不将模拟成交标为实盘。Gate / OKX / Binance 的现货规划保留。
8. **OpenClaw + 消息：** 飞书机器人（通过 OpenClaw）、Telegram 可在 Smart Money UI 中添加、更换、测试、启停，通知服务故障不影响交易。
9. **日日新迁移：** OpenClaw 从本地 Ollama / llama.cpp 主模型迁移到商汤日日新免费模型候选 `sensenova-6.8-flash-lite`；原有 Gateway、通知通道和本地模型保留回滚能力。
10. **最少调试：** 高频操作、密钥更换、模型选择、平台切换、风险参数、通知及记忆管理通过 UI 完成；高级设置折叠，错误给出可操作的诊断，不要求普通用户编辑 `.env` 或运行命令。
11. **真实功能优先：** 不做只有前端的空按钮；每个用户可见功能必须有真实后端状态、数据链路及失败处理。
12. **GitHub 安全：** 未经用户明确授权，不创建公开仓库、不发布/推送主工程、不覆盖远程分支；旧 `smart-money-mobile` 不视为 Windows 主工程。

### 1.3 需要在开发中明确化的冲突

- **“所有功能可用”与“外部 API 未验证”**：真实现货交易是 Stable 硬性目标；Polymarket 事件预测的只读/模拟功能也要真实可运行，但事件合约专用实盘如未验证，不能冒称可用。最终发布能力清单必须按交易所和产品分别标记。
- **“参数尽量不硬拦截”与“防错交易”**：推荐范围超限时只提醒；交易所最小金额、数量精度、余额、幂等、产品能力、过期信号等执行不变量必须硬校验。
- **“AI 自主成长”与“实盘可控”**：可自动积累记忆、提出新假设、改进模拟预测；不得未经明确授权自增杠杆、提高风险、修改实盘策略参数。
- **“最少调试”与“高可靠”**：通过向导、自动健康检查、诊断与一键恢复降低用户负担，不减少工程测试和真实资金验收。

## 2. 推荐系统架构与核心边界

```text
React/TypeScript UI：交易工作台 | AI 中心 | 两种挑战 | Brain | 设置中心
                    |
             Python API / Application Services
                    |
   MarketScheduler ---> Snapshot/Indicators ---> Rule Engine / AI Worker
                    |                            |
      独立保护性通道（止损/查单/对账）      有时效的结构化决策
                    |                            |
                    +------> 独立风控 + 幂等订单意图 <----+
                                      |
             ----------------------------------------
             |                       |               |
      Spot Live Executor       Paper Executor    Event Research
             |                       |               |
       Gate/OKX/Binance      模拟账本/成本      预测/模拟/结算
             |                       |               |
             +-------------- 持久化事件账本 ------------+
                                      |
                      Brain/Memory、回放与绩效分析
                                      |
                   异步通知队列 ---> OpenClaw ---> 飞书/Telegram
```

**严格解耦：** AI 推理、长期记忆写入、OpenClaw 机器人发送、图表渲染均不得成为止损、订单查询、风控及数据对账的同步依赖。**模型分工：** OpenClaw 对话/通知主模型与 Smart Money 交易决策模型独立配置，可以相同，也可以不同。

### 2.1 最小接口契约（以现有源码命名为准）

- `MarketSnapshot`：平台、产品、交易对/事件 ID、来源时间、接收时间、版本、有效期、数据质量。
- `Decision`：唯一 ID、snapshot ID、模型/规则版本、配置版本、方向、概率、预期收益、`SKIP`/参与、截止时间、证据。
- `RiskVerdict`：风险校验结果、阻止原因、允许订单预算、可用余额、交易成本和精度解释。
- `OrderIntent`：平台+账户+产品+唯一幂等键；关联源决策、请求时间、目标数量和风险预算。
- `OrderState`：待发送、待确认、已接受、部分成交、已成交、已取消、已拒绝、未知状态、已对账。
- `LearningRecord`：会话/轮次、输入快照、预测、结果、校准情况、观察/假设/已验证/失效标签、来源证据。
- `NotificationEvent`：事件 ID、事件类型、通道、目标、重试次数、发送状态、模拟/真实标记。

## 4. Phase 4 可靠性修复：优先级最高

### 4.1 AI 调度解耦

- 审计 `ai/provider.py`、`terminal/runtime.py` 以及实际调用链；采用现有项目适配的异步任务或隔离工作器、有界队列、超时和取消机制。
- 行情扫描、保护性退出、账户对账、交易所流同步和订单状态更新不等待模型；通知与记忆写入亦为独立队列。
- 队列满、模型 429、网络失败或模型卡住时，丢弃过期决策并记录原因；按照用户已设置的策略切换规则引擎、暂停新仓或等待人工，**不得自动加大风险**。

### 4.2 决策失效与风控

- 交易动作前重检快照年龄、市场数据质量、平台/账户/产品、模型和配置版本、事件窗口、余额及订单限制。
- 超时 AI 返回的提案一律不能直接执行；`SKIP` 必须完整入账并在 UI 可追踪。
- 所有真实订单先独立风控、再创建幂等订单意图；失去时效即停止新交易，不影响既有持仓保护。

### 4.3 止损与订单生命线

- 区分**本地循环止损**与**交易所已确认的保护单**；不允许将本地监控冒充交易所托管。
- 订单提交超时 -> `UNKNOWN` -> 查询交易所订单/成交 -> 明确状态后处理；禁止直接再次提交形成重复订单。
- 正确处理部分成交、部分撤单、手续费、实际均价、重启后恢复、余额差异、切换交易所时遗留未完订单。
- 实盘启动前，自动检查 API 可达性、授权、余额、市场规则、保护措施、事件账本及数据一致性；出现阻断项不得静默跳过。

## 5. 真实交易交付范围及验收

- v1.0 **不是只能模拟**。Gate、OKX、Binance 的通用现货是目标交易所产品，采用单平台执行，不要求同时在三家实盘下单。
- 实际支持范围由官方 API、账户权限及经过执行器测试的能力注册表决定，逐所报告：行情/余额/下单/撤单/查单/部分成交/精度/费率/风险/重启恢复。
- 真实交易验收须按最小合规订单规格，在用户明确授权后执行受控的小金额真实订单，核对交易所回执、成交、余额、费用、取消/退出及保护状态。未完成真实测试则不能宣称该平台已经实盘验收。
- 停止程序不等于交易所仓位平仓；必须向用户明确告知未完订单/持仓，保护任务不能在静默退出时丢失。
- 推荐值超出区间时警示但允许保存；交易所硬性交易规则、无法验证的订单状态、非法数据及执行权限必须强制校验。

## 7. Polymarket 与事件预测技术准备

- **已核对通用 Gate API v4：** 提供现货、杠杆、合约等产品的一般行情和认证交易能力，包含 REST 与 WebSocket；这是通用能力结论，不是事件合约专用自动交易的确认。
- 事件预测模块独立于现货执行器，区分平台事件ID、市场ID、结果Token标识、标的、事件起止、参考基准、报价与官方结算来源。优先研究加密资产短周期涨跌市场；币种及5分钟等周期必须通过实际市场发现确认，不预设一定存在。
- 事件结果不能以普通现货 K 线涨跌替代官方结算；报价缺失时只允许明确标注的假设性回测；不允许产生看似真实的模拟成交订单号。
- 二元事件单张预期净收益按 `EV = 校准后胜出概率 × 胜出兑付额 + (1 - 概率) × 失败兑付额 - 实际买入价 - 单张估计成本` 计算；结算资产、兑付规则、费用、滑点及可成交报价以具体市场为准，不套用 Gate 的 USDT 假设。
- Gate 事件合约接入状态及统一接口设计，以文末 2026-11-04 修订为准。

## 8. Smart Money Brain：模拟开始学习（v1.0 必交付）

### 8.1 真实闭环

`开始模拟 → 快照及预测持久化 → 模拟订单/成本 → 可信结算 → AI 反思 → 假设/经验入库 → 后续按场景检索 → 独立评估`。

- 本地长期记忆优先复用现有数据库，不贸然新建第二套基础设施。可以逻辑划分 `identity / preferences / observations / hypotheses / lessons / reflections / snapshots / exports`。
- 每条经验含生成时间、来源决策与快照、模型版本、适用市场/周期、证据状态、版本和失效条件。
- 支持多模型共享（GPT/Claude/Gemini/DeepSeek/日日新等），但隔离不同交易会话、平台、模拟与实盘数据来源；用户可在 UI 搜索、纠错、暂停写入、导出、恢复。
- 只从已确认且可追溯的结算结果生成“验证后经验”；单次盈利、错误数据、未结算轮次不能直接认定策略有效。
- 对照“有记忆/无记忆”模型，在相同历史条件下按时间前向评价 Brier Score、Log Loss、净收益、最大回撤、SKIP 比率；严格避免未来数据泄漏和测试集反复调参。
- 长期记忆写入失败不阻塞真实订单或保护性任务；AI 经验只能提出建议，不能未经授权修改实盘风控。

### 8.2 用户界面

## 15. 2026-11-04 修订：事件市场平台可用性与统一接口

### 15.1 Gate 当前结论

- 已实际验证 API V4 私有签名及 Wallet 汇总只读查询返回 HTTP 200，响应存在 `event_contract` 账户分类。此前旧密钥 Wallet 查询返回缺少权限。

### 16.2 用户已确认的产品方向

- UI：新手模式与专业模式并存。两种模式共享同一后端、交易引擎、账户状态和确定性风控；模式切换只改变信息密度、引导和可见配置，不改变权限或风险上限。
- AI：采用多角色 AI 团队，包含市场分析师、策略研究员、AI 交易员、AI 风险顾问和 Brain。角色是职责边界，不要求一角色一模型；初期允许共享 Provider/模型，以实际评估决定是否拆分。
- 盈利目标：稳健策略作为主线，同时保留更高收益策略的独立研究线。高收益研究线不得自动改变稳健主线的风险预算、实盘配置或资金权限。
- 继续使用现有 Python 后端、React/TypeScript 前端和当前持久化/执行体系；优先增量演进，不重建工程，不为多 Agent 或 UI 改版引入不必要的新框架。

### 16.3 UI 双模式与信息架构

建议把现有导航整理为六个工作区，具体映射先通过现有路由和页面盘点确定，不删除原有能力：
1. 交易总览：资产/净值、当日与累计表现、风险、运行状态和待处理事项。
2. AI 智能中心：角色状态、分析证据、提案生命周期、Brain 引用与复盘。
3. 交易工作台：策略、会话、持仓、订单、保护和执行状态。
4. 研究与回测：历史回测、事件研究、挑战、样本外和 Walk-forward。
5. 绩效分析：净收益、费用、滑点、回撤、Profit Factor、Expectancy 和策略对照。
6. 设置中心：交易所、模型、Brain、通知、预算和高级设置。

新手模式使用推荐模板、分步向导、中文解释和金额化风险说明；专业模式保留完整参数、原始指标、订单生命周期和研究工具。高级设置采用渐进披露，不移除专业能力。两种模式必须共享同一参数校验和服务端风控。UI 显示的运行环境、数据来源和模拟/真实标记必须来自后端真实状态，不允许仅由前端切换标签伪造。

### 16.4 多角色 AI 团队：职责与实时路径

- 市场分析师：读取有时间戳和质量标记的行情快照，输出趋势、波动、流动性及市场状态判断。
- 策略研究员：主要执行异步研究、策略假设、参数实验、失效分析和样本外评价；研究成果以带版本和适用范围的研究制品提供，不应在每个实时交易周期重新进行深度研究。
- AI 交易员：基于当前有效快照、已验证研究制品和必要上下文，生成 BUY/SELL/HOLD/SKIP 结构化提案。
- AI 风险顾问：提供独立风险意见、异常提示和拒绝建议；其意见不能替代确定性风控，也不能授予执行权限。
- Brain：提供有来源、有时间边界的缓存记忆检索；异步保存观察、预测结果和复盘。记忆不可用时不得阻塞保护、对账或安全拒绝路径。

实时协作采用并行、截止时间约束和部分结果策略，不采用所有角色依次调用且必须全部完成的串行链。协调器按任务类型定义最低必要输入、允许等待的角色和截止时间；研究员、深度复盘和长期记忆写入默认在后台运行。AI 角色缺失、超时或输出无效时，按已配置策略 SKIP、暂停新仓或回退到规则引擎；不得因为少一个 AI 回复而放宽风控。

### 16.5 新增核心模块：AI Proposal Freshness Manager

实时 AI 提案容易过期，必须把新鲜度管理作为 AI 与执行器之间的独立基础设施，而不是仅依赖模型提示词或单一固定 TTL。建议先审计现有提案有效期、快照版本、配置版本和执行入口，复用现有实现；只有缺口得到证实后才增加最小模块，避免重复造轮子。

每份交易提案至少关联：
- proposal_id、task_id、symbol/market_id、venue、account_scope、product_scope；
- snapshot_id、行情来源时间、接收时间、序列/版本、数据质量和市场状态；
- 参考价格、必要时的 bid/ask、点差、深度/流动性摘要、波动环境；
- strategy_version、model/provider、prompt/schema 版本、config_version、risk_config_version；
- position/balance 或账户状态版本、创建时间、截止时间、最大有效期；
- 价格偏移/滑点边界、证据引用、决策相关 ID 和幂等关联信息。

新鲜度判定采用多维硬门槛：
1. 时间：不得晚于策略与周期允许的截止时间；TTL 是最大上限，不是唯一判断条件。
2. 行情：快照必须可用、时间单调、序列无未解释缺口；不能仅因 AI 返回较晚就假定行情仍有效。
3. 价格：当前可执行参考价相对提案参考价的偏移必须在策略配置边界内，并计入 bid/ask、点差和预估滑点。
4. 波动与流动性：市场状态、波动区间、点差或可用深度发生超阈值变化时，提案失效或重新评估。
5. 状态版本：持仓、余额、账户、策略配置、风控配置、交易所规则或会话状态发生影响决策的变化时，旧提案不得直接执行。
6. 作用域：平台、账户、产品、交易对/事件市场和模拟/真实环境必须完全匹配。

TTL、价格偏移、点差、波动和深度阈值按策略类型、周期、市场状态和平台规则配置，并通过历史回放与前向模拟校准；不得把示例数值写成通用常量，也不得为提高提案通过率而放宽门槛。关键数据缺失或新鲜度无法证明时默认拒绝新仓提案，既有持仓保护继续独立运行。

建议提案状态：PENDING、VALID、SUPERSEDED、STALE、EXPIRED、REJECTED、CONSUMED。状态转换必须单向、可审计；CONSUMED 不可重复消费。SUPERSEDED 表示被更新提案替代，STALE 表示证据/状态变化使其不再可靠，EXPIRED 表示超过截止时间，REJECTED 表示验证或风控拒绝。旧状态与拒绝原因保留，不得静默覆盖。

防止迟到结果复活：每个标的/决策作用域使用单调 generation 或 fencing token；新任务取代旧任务后，旧任务即使无法真正取消、稍后仍返回，也不得覆盖新提案、更新有效状态或进入执行队列。任务取消只是资源优化，不是安全保证。执行器入口必须再次校验状态、版本、有效期和幂等键；生成时的检查不能代替执行前的最后检查。

### 16.6 延迟预算、并行调度与安全回退

- 每个策略/周期定义端到端决策延迟预算：行情接收、快照构建、AI 调用、协调、最终新鲜度检查和风险校验分别计时。
- 协调器支持并行调用、截止时间、有限并发、有界队列、去重、熔断和任务代次隔离；不得无限积压旧任务。
- 不要求每一轮调用全部五个角色。实时最小路径优先使用当前快照、AI 交易提案和确定性风控；市场分析可并行提供上下文；研究员和 Brain 深度工作异步完成。风险顾问可按风险等级参与，但不能替代系统硬风控。
- 仅当必要角色结果在截止时间内返回、快照仍新鲜且确定性风控通过时，才可进入后续执行流程。超时/不完整结果按策略选择 SKIP、暂停新仓或规则回退；任何回退仍经过相同硬风控。
- 旧任务即使在超时后返回，也必须被 fencing token、proposal generation 和版本校验拒绝。超时取消不保证底层网络或模型请求停止。
- Brain 检索采用有时效的缓存/预取，记忆写入与复盘走后台队列；必须保留记忆来源时间，禁止将决策时点之后产生的记忆用于历史回测或样本外评价。

### 16.7 稳健主线与高收益独立研究线

建立两条隔离的策略生命周期：
- 稳健主线：以成本后正期望、可控回撤、低尾部风险和跨市场状态稳定性为优先；研究趋势、动量、均值回归、波动过滤和组合风险。
- 高收益研究线：允许研究更高波动、更高换手或事件型策略，但只能在隔离回测和模拟环境运行；独立预算、独立账本、独立风险上限和单独报告。

策略生命周期统一为 Idea → Research → Backtest → Out-of-sample → Walk-forward → Paper Forward → Candidate → 人工批准。候选策略不得自动升级为正式策略；实验线不得自动改变稳健主线参数或账户资金。策略淘汰、暂停和降级也必须留存证据。

统一评价至少包含成本后净收益、Profit Factor、Win Rate、Expectancy、Maximum Drawdown、Sharpe/Sortino、交易次数、费用/滑点、资金占用、预测 Brier Score/Log Loss 和 AI 调用成本。测试前冻结数据切分、费用假设、阈值及搜索范围；记录所有尝试，防止未来数据泄漏、幸存者偏差和反复调参造成的过拟合。任何历史/模拟成绩不得表述为真实收益或未来收益保证。

### 16.8 规则 / AI / AI+Brain 配对实验

建立三组可重复对照：
- A：纯规则引擎；
- B：AI 增强引擎；
- C：AI + Brain 引擎。

三组必须使用相同时间窗口、同一可用信息集、相同资金预算、相同执行假设、费用和滑点口径。记录每次决策时可见的数据，确保 Brain 不读取决策时点之后的信息。采用时间序列样本外与 Walk-forward 评价，预先定义最低样本要求和统计检验；对多策略、多参数尝试进行试验记录和过拟合控制。若 AI 的成本后增量收益或风险调整收益未表现出稳定改善，不得宣称 AI 优于规则引擎。

| S2 AI 协调与新鲜度 | 角色协议、并行/截止时间、Proposal Freshness Manager、fencing token、迟到结果隔离 | 覆盖时间过期、价格偏移、波动/流动性变化、快照乱序/缺口、配置/持仓变化、超时迟到、重复消费；过期提案进入执行入口次数为零 |
| S3 Brain | 缓存检索、时间边界、来源引用、异步写入、复盘和有/无记忆对照 | 不阻塞实时保护；历史评价无未来信息泄漏；引用可追溯 |
| S4 策略验证 | 双策略研究线、成本/滑点模型、样本外、Walk-forward、策略淘汰 | 数据、成本、参数和结果可复现；不以单一回测收益批准策略 |
| S5 Paper Forward | 规则、AI、AI+Brain 实时影子/模拟配对 | 记录决策延迟、提案过期率、净收益、回撤和 AI 成本；不连接真实下单权限 |
| S6 Release Candidate | G2 生产 Runtime/UI 闭环、Windows 安装/迁移/恢复、全站端到端、安全与依赖审计 | P0 阻断为零；发布清单逐平台/产品列证据；真实账户验收仍须独立授权，未完成时不得标 Stable |

阶段 S0 是当前开发首要任务。S1 的信息架构和设计可以并行准备，但在 S0 关闭前不进行大规模 UI 重写；S2 的接口设计可只读预研，正式实现须先核对现有提案/过期机制，采用最小增量方案。

### 16.10 必须记录的 AI 实时质量指标

- 提案生成延迟与端到端决策延迟 P50/P95/P99；
- 提案过期率、SUPERSEDED 比率、各类 STALE/EXPIRED/REJECTED 原因分布；
- 从提案生成到最终风控校验的耗时；
- 旧任务迟到返回、fencing token 拒绝和重复消费次数（安全验收中旧结果执行次数必须为 0）；
- 快照年龄、序列缺口、价格偏移、点差、深度和波动变化；
- AI Provider 超时、限流、错误、回退比例及每笔/每日模型成本；
- Brain 缓存命中率、记忆引用比例和检索延迟。

UI 必须显示提案生成时间、行情源时间、参考价格、剩余有效期/失效原因、使用的快照和配置版本。不能仅显示一个“AI 建议有效”标签。

### 16.11 阶段交付和验收要求

每一阶段均须提供：
- 当前代码基线和工作区状态；
- 任务目标、允许修改范围及明确禁止修改的部分；
- 修改文件及原因；
- 实际执行命令、运行环境、通过/失败/跳过数量；
- 未执行测试及原因；
- 已知风险、回滚点和下一步建议。

同一时间只允许一个写入者修改同一工作区。任务交接前，原写入者必须停止修改并保存可恢复检查点，提供代码差异、最后提交和测试证据。项目所有者保留产品范围、生产依赖、数据库迁移、删除、账户权限、真实交易授权和发布的最终决定权。

## 16.12 2026-11-10 产品方向收敛：先交付可用的现货与永续交易终端

本节为当前最新且优先级最高的产品决定。若本计划书早期章节、旧路线图或历史记录与本节冲突，以本节和当前源码证据为准。旧内容作为历史决策保留，不代表仍获批准的当前开发任务。

### 16.12.1 产品定位与 v1.0 目标

Smart Money AI Trader 的目标是一个可在 Windows 本地运行的 AI 辅助量化交易终端，**现货与永续合约为第一优先级**。模拟交易是优先测试和验证方式；真实交易是 v1.0 必须支持的正式能力，不得把产品目标收缩为纯模拟软件。

v1.0 对现货和永续均要求形成模拟与真实两条完整路径：行情与规则检查 → 策略/AI 决策 → 确定性风控 → 订单提交 → 成交与费用核对 → 持仓管理 → 止损/止盈 → 平仓 → 绩效记录 → 重启与异常恢复。真实交易功能完成代码和平台验收后仍需独立授权才能使用。

当前 main 的实际边界必须如实记录：新建实盘会话目前仅允许现货；永续存在部分连接/历史兼容代码，但新实盘会话明确拒绝非现货产品。现货实盘代码路径也尚未通过完整平台 demo、真实账户、托管保护单和资金对账验收。因此，现货实盘和永续模拟/实盘均不能标记为已完成。

Polymarket 事件市场移至现货与永续主线之后的后续版本，不纳入当前基础版本开发顺序。Gate 事件接口保留现有研究记录，不作为现阶段交易主线。

### 16.12.2 基础版本必须具备的八类能力

这些是产品能力领域，不要求拆成八个独立服务或重建现有架构：

1. **市场数据：** 实时/历史行情、K线、成交量、盘口、永续资金费率、交易规则、数据时间戳和数据质量检查。
2. **策略：** 趋势、动量、突破、均值回归、波动过滤等可解释策略；明确入场、退出、适用市场和风险边界。
3. **AI 决策：** 先把一个 AI 决策流程做得稳定、及时、可解释；输出买入、卖出、持有/观望或跳过建议，并提供证据、风险、失效条件和调用状态。多角色团队不是基础版本的前置条件。
4. **风险管理：** 单笔风险、仓位、最大账户风险、每日亏损、最大回撤、止损/止盈、永续保证金与强平风险、异常停机。AI 不能绕过确定性风控。
5. **交易执行：** 现货/永续，模拟/真实，订单状态、部分成交、撤单、幂等、未知订单阻断、交易所对账、重启恢复和账户隔离。
6. **回测与盈利验证：** 统一计算手续费、滑点、永续资金费率和净收益；支持样本外、Walk-forward 和前向模拟；避免未来数据泄漏和过拟合。
7. **账户与绩效：** 余额、资产、持仓、订单、成交、已实现/未实现盈亏、费用和交易复盘。
8. **系统管理与通知：** 保留并完善现有通知、异常告警、运行状态、日志、配置、备份与恢复。通知不得阻塞交易、保护和对账流程。

### 16.12.3 已有能力保护规则

优先复用当前 Python、FastAPI、React/TypeScript、SQLite、CCXT、订单状态、风控、Brain、G1/G2 和 UI 实现。不得为了“简化”而重建工程或删除已有成果。

以下能力默认保留：通知系统及其通道、Brain、G1/G2 已完成成果、策略实验室、历史回测、实验报告、交易流水、账户与持仓管理、已有风险和执行模块，以及用户未明确批准删除的其他功能。

**挑战功能移除说明：** “24小时翻倍挑战”已获准移除。先清点路由、配置、调度器、数据库字段/表、测试、报告、文档和打包白名单，再只删除挑战专属实现与入口；保留历史报告/记录。不得连带影响 G1 自动预测挑战、通用策略实验室、回测、通知或 Brain。

### 16.12.4 开源优先：先找成熟实现，再决定自研

每项功能开发前，先检查当前仓库已有实现，并在 GitHub 评估是否存在适合复用的开源库或项目。适配后可优先使用成熟依赖、独立组件、协议适配器、算法实现或测试工具，不要求每项功能全部自行编写。

评估必须记录：
- 上游仓库、具体版本/commit、维护活跃度和已知安全问题；
- SPDX 许可证、NOTICE、版权保留和分发义务；GPL/AGPL 等强 copyleft 代码须先完成合规审查；
- Windows、Python、Node、运行时和现有数据库/数据契约兼容性；
- 功能重叠、性能、依赖体积、供应链和升级风险；
- 最小隔离原型、回归结果、采用/不采用原因和撤销方案。

当前可复用或候选方向：
- **CCXT：** 当前已有依赖，优先完善现有交易所适配，不另建重复连接层。
- **Lightweight Charts：** 当前已有前端图表依赖，优先复用。
- **Hummingbot（Apache-2.0）：** 可评估连接器、订单执行和市场数据组件；避免整套搬入并形成第二套执行器/账本。
- **Jesse（MIT）：** 可评估策略、回测、分析与复盘的可隔离实现。
- **Freqtrade（GPL-3.0）：** 可研究策略接口、回测与偏差检查；复制或形成衍生集成前必须先评估许可证义务。
- **TA-Lib（BSD 系列许可）：** 继续作为指标参考；与当前指标口径对照后再决定是否用于生产。
- **QuantStats（Apache-2.0）：** 可评估绩效指标和报告，不替代交易账本。
- **Optuna（MIT）：** 仅在回测、样本划分和过拟合控制成熟后评估离线参数搜索。
- **Hypothesis（MPL-2.0）：** 可评估用于订单、风控、资金守恒等属性测试。

上列是候选，不代表已经安装或批准集成。若现有实现已足够，不为使用开源项目而引入新依赖。具体采用记录见 docs/OPEN_SOURCE_AUDIT.md。

### 16.12.5 盈利验证标准

盈利是需要验证的目标，不是产品承诺。每个策略至少报告：毛收益、手续费、滑点、永续资金费率、净收益、交易次数、胜率、盈亏比、Profit Factor、Expectancy、最大回撤和适用时的 Sharpe/Sortino。

必须采用时间顺序数据切分、样本外测试和 Walk-forward；记录策略版本、参数、数据来源、费用假设和所有实验尝试。AI 是否有增量价值，必须与相同条件下的纯规则基线比较。没有稳定的样本外和前向证据，不得宣称盈利策略或 AI 优势。

### 16.12.6 AI 可用性与提案时效

基础版本先聚焦单一可靠决策链，不先开发五角色 Agent 团队。先解决模型配置、连接测试、清晰错误、超时、限流、预算、结果结构化、日志和失败回退。

AI 提案必须绑定行情快照时间/版本、参考价格、交易对、平台、产品、账户环境、策略版本、风险配置和持仓/余额版本。执行前重新检查时间、价格偏移、点差、波动、流动性和状态版本；旧任务迟到返回不得覆盖新结果。现有过期检查和异步 Worker 应先审计并复用，再补足实际缺口。模型失效时不影响保护、对账和硬风控。

### 16.12.7 用户界面与操作原则

减少开发者术语，使用“首页、交易、策略与复盘、设置”等用户可理解的入口。常用操作应能完成查看行情、选择策略、启动模拟/实盘、查看订单/持仓/收益、停止新开仓和查看告警。专业指标可以保留在详情页或高级模式。

导航整理只改变信息组织，不删除已有功能、历史记录或后台能力。通知、Brain、G1/G2、实验报告等通过合适的二级入口保留。

### 16.12.8 实施顺序

| 顺序 | 工作 | 完成标准 |
|---|---|---|
| 0 | 只读保全审计与集成阻断排查 | 确认本机/远端基线、差异、已知失败复现入口和可回滚点；不覆盖本地工作 |
| 1 | 现货基础闭环 | 模拟路径完整；真实执行路径完成平台 demo、订单、费用、保护、恢复和对账验收 |
| 2 | 永续基础闭环 | 模拟和真实路径分别实现开平仓、保证金、杠杆、资金费率、强平风险、止损和对账 |
| 3 | AI 可用性 | 一个 AI 决策链稳定、可解释、时效有效、成本可测；规则回退可靠 |
| 4 | 盈利验证 | 成本后回测、样本外、Walk-forward、前向模拟和规则/AI 对照可复现 |
| 5 | UI、通知与发布整合 | 用户操作简洁；现有通知与其他能力保留；Windows 安装、升级、恢复和安全验收完成 |

一次只实施一个清晰任务，避免多个写入者同时修改同一工作树。先复现问题，再做最小修复；每项任务必须有测试证据、差异、风险和回滚点。



## 16.13 2026-11-11 Copilot 审计采纳：v0.1 收敛与成果保护

本节采纳项目所有者提供的 Copilot 全面审计建议。它对 v0.1 的交付范围作收缩，但**不推翻 §16.12 确定的 v1.0 最终产品方向**。两者层级不同：v0.1 是最小可用里程碑，v1.0 仍保留现货/永续、模拟/真实交易的完整目标。

### 16.13.1 当前唯一主线：最小现货纸面交易垂直切片

v0.1 的目标是证明用户能安装、理解并完成一条端到端流程：

安装 → 启动 → 获取公开行情 → 规则信号 → 纸面成交 → 手续费/滑点后净值和回撤 → 暂停/停止 → 重启恢复 → 导出记录。

范围限定为一个通过本机只读审计确认稳定的交易所公开现货数据源，以及 1–3 个规则/历史数据完整的现货交易对；一套已有规则策略；纸面交易；AI 可选解释/复盘。具体交易所和交易对须先检查本机工程、数据源与测试，不得凭记忆或默认配置擅自指定。

v0.1 不开放真实下单、永续执行、事件合约执行、多交易所扩张、新通知渠道、新 Agent/挑战和新主导航页面。以上是阶段性排除，不是 v1.0 永久取消。v1.0 最终方向仍以 §16.12 为准。

### 16.13.2 现有劳动成果保护：隐藏不等于删除

默认保留所有已有模块和历史证据，包括现货/永续连接器、真实交易相关代码、风险和保护、订单状态与恢复、AI Provider、Brain、通知 Outbox/Worker/Gateway、G1/G2、Polymarket 只读研究、策略实验室、历史回测、实验报告、交易流水、账户/持仓、测试、依赖许可证和 Windows 工具。

v0.1 主导航只突出：首页、运行、历史、设置。其他研究、事件预测、通知、Brain、G1/G2、挑战、实验报告和诊断入口可移动到实验区/二级入口或暂时隐藏，但不得因此删除 API、数据库表、模块、历史数据、测试或打包清单。

“24 小时翻倍挑战”是唯一已明确批准退出当前产品范围的旧功能。先隐藏入口并检查路由、配置、调度器、数据库、测试、报告、文档和打包依赖，再只清理挑战专属代码。G1 自动预测挑战和通用研究/回测能力必须保留。

### 16.13.3 AI：先作为解释器，不作为 v0.1 交易决策者

v0.1 AI 默认关闭。开启后仅解释规则信号、列明风险或复盘历史交易；不直接创建订单，不改变规则策略信号，不绕过风控。界面显示 Provider、模型、调用延迟、估算成本、失败原因和回退状态。

后续使用固定 100–300 个样本，保存行情快照、提示词/模型版本、输入输出、延迟和成本；与纯规则基线比较一致性、可解释性和成本，再通过同数据、同费用口径的 A/B 与样本外测试决定是否扩大 AI 决策范围。JSON 合法或 Mock 通过不能证明 AI 有交易价值。

### 16.13.4 盈利研究门槛

当前策略是研究基线，不得宣传为盈利策略。统一报告训练/验证/样本外时间切分、买入持有和不交易基准、手续费、滑点、最小成交单位、永续资金费率、交易次数、胜率、盈亏比、Profit Factor、Expectancy、最大回撤、收益波动、市场状态、参数敏感性、消融实验、AI/规则 A/B 和失败区间。禁止未来数据泄漏。

### 16.13.5 UI 收敛

主导航四入口：首页、运行、历史、设置。首页聚合运行状态、模拟资产、净值、收益、回撤和风险告警；运行页完成市场/策略选择与纸面会话控制；历史页展示订单、成交、费用、净值、回撤和导出；设置页管理数据源、策略、可选 AI 与风险上限。

内部术语如 Opportunity Score、Position Book、Event Feed、Paper/Live、动态准入等优先改为清晰中文或移入高级详情。此项是信息架构和入口收敛，不要求大规模重写组件。

### 16.13.6 稳定性与发布阻断

按优先级复现并关闭：
1. 保护单浏览器流程超时；
2. 86,401 点回放图表内存失败；
3. G1 Worker 遇 Brain 数据库 busy 后异常退出；
4. 浏览器验收的 ConnectionResetError；
5. 较早提交 `d64371abfcef4ebdbd71d05a62ebe0e6ce6ab57d` 的 Windows CI 曾因依赖审计 JSON 的 npm lock SHA 与实际 lockfile 不匹配而出现 937 passed / 1 failed。2026-11-11 只读核验时，后续 PR HEAD 为 `40f47c3f58a31eab8786016b8e29320112b7f527`，但该 HEAD 没有 Actions/check 结果；因此旧失败不是后续 HEAD 的测试结果，后续 HEAD 也不能视为已通过。文档更新后 PR HEAD 会继续变化，必须在最终 HEAD 上重新执行依赖审计与适当 CI；不能只手改 SHA、降低测试或跳过测试。

v0.1 发布还需干净 Windows 目录安装/启动/停止/恢复证据、前端构建、关键浏览器流程、全量离线测试和 GitHub Actions 必需检查通过。测试日志有未解释异常时，即使退出码为 0 也不能算通过。

### 16.13.7 协作和开源流程

一个活跃写入者、一个任务分支、一个开放功能 PR。文档更新随功能/范围 PR 同步；不要另起重复路线图分支。PR 必须通过目标测试和最小启动验证；已知失败阻止合并，除非项目所有者在明确知情后另行决定。main 是唯一共享稳定基线，但本机运行目录和工作树必须先只读核验，不能直接 reset/clean/覆盖。

每项功能开始前先查本项目已有代码和 GitHub 开源项目；成熟实现适配合适时优先复用。检查固定版本、许可证、维护状态、安全公告、Windows/Python/Node 兼容、依赖体积、架构重叠、隔离 POC 和回滚方案。不得为了复用而整套引入另一套交易终端。

### 16.13.8 执行前置条件

下一轮由 GitHub Copilot 作为唯一活跃写入者。开始前必须完成本机所有工作树、运行目录、数据库、备份和远端 main 的只读审计；核实 2026-11-10 历史 SHA 是否仍成立。不得假定主工程目录等于远端 main，不得覆盖本地独有成果。先提交审计报告和 v0.1 任务拆分，再由项目所有者确认后开始第一项实现。
