# Smart Money AI Trader · 产品决策池

> 更新：2026-11-10。此处记录已批准范围、待评估开源项目和后续候选。它不是自动执行清单；当前实施优先级以主计划 §16.12 为准。

## 最新已批准决定

1. **v1.0 主线：** 现货与永续合约，模拟交易优先验证，真实交易必须作为正式产品能力完成。
2. **AI：** 先让一个 AI 决策流程真正可用，不先建设五角色团队。
3. **盈利验证：** 成本后净收益、最大回撤、样本外、Walk-forward 和前向模拟；不承诺收益。
4. **开源优先：** 每项功能先检查 GitHub 上是否有成熟且兼容的实现；适配合适时优先复用，必须审查许可证、维护状态、Windows 兼容、依赖和安全。
5. **延后：** Polymarket、多角色 AI、更复杂的自动优化和更多平台，不阻塞现货/永续基础版本。
6. **明确移除：** 24小时翻倍挑战，待依赖审计后只清理挑战专属代码。
7. **明确保留：** 通知系统、Brain、G1/G2、策略实验室、历史回测、实验报告、交易流水、账户/持仓和所有未被用户明确批准删除的能力。

## 当前核心能力清单

| 能力 | v1.0 目标 | 当前事实边界 |
|---|---|---|
| 市场数据 | 现货与永续的实时/历史数据、盘口、规则、资金费率 | 现有公开现货数据较多；永续数据/完整规则链路待验收 |
| 策略 | 可解释入场/退出和风险参数 | 现有规则策略保留，盈利能力未证明 |
| AI | 一个稳定、低延迟、可解释的决策链 | Provider/Worker/Brain 已有代码，默认模型未配置，真实质量未证明 |
| 风控 | 现货与永续的独立产品规则和统一硬风控 | 有部分实现；真实平台保护和保证金路径待验收 |
| 交易 | 现货与永续，模拟与实盘 | 新实盘会话当前只允许 spot；swap live 未实现/被阻断 |
| 回测 | 成本后结果、样本外与前向验证 | 现有历史研究保留，需统一成本口径并验证 |
| 账户绩效 | 资产、持仓、订单、成交和盈亏 | 现有页面与账本保留，需完成端到端核对 |
| 通知 | 现有通道、异常告警和持久化重试 | Outbox/Worker/协议适配已有代码，生产 Runtime/UI 闭环待完成 |

## 开源项目采用流程

先查现有代码和依赖，再在 GitHub 搜索适合的项目。只有当第三方实现能明显减少维护成本、补足可靠能力或提高测试质量时才采用。记录具体仓库和 commit、许可证、维护状态、安全公告、Windows 兼容性、依赖体积、接口适配、隔离测试、回滚方式。不要为了“用了开源”而引入重复框架；不要整套搬入另一套交易终端。

## D. 候选进入正式实施时的验收清单

- 先核对是否属于原 v1.0 范围，以及现有代码是否足以完成；不能为了新增库而新增功能。
- 记录明确的版本、许可证、维护情况、依赖体积、Windows/Python 兼容性及分发条件。
- 在隔离环境做最小 POC；与原实现对照，必要时补基准数据和回归测试。
- 涉及交易指标、风险或订单时，必须验证行为差异，并且不允许悄悄改变实盘参数、订单状态或账户数据。
- 为每项候选留下“采用 / 不采用 / 延后”的原因、测试证据与可执行回滚步骤。
- 若声称更有盈利优势，需有净费用、基准、样本外、稳定性和风险指标证据；不能只展示最好的历史曲线。

## E. 私有真实订单账本驱动的审计样本与候选改进（2026-11-04）

> **案例编号：`CASE-GATE-LEDGER-20261102-03`。** 已将一组真实事件合约资金流水作为**私有离线审计样本**归档，并形成逐类对账报告。公开仓库仅记录脱敏工程结论与决策，不上传用户原始逐笔订单、账户标识、资金流水或个人损益金额。该案例**不是**实盘交易策略验证、预测胜率证明或 Gate 事件合约 API 可用性证明。

### E1. 已核对的数据事实和限制

- 私有样本合并后为 **407 条账单分类记录**：**374 条交易类**（买入、退还、卖出、结算）和 **33 条账户划转**。存在不同账单分页重叠，整合过程中已按来源排除已知重复片段。
- 已按原始金额正负号核算交易现金流，并用划转和条件性理论期末余额进行**独立的会计等式核对**；完整精确金额、日期范围、Excel 原件、哈希与核对口径放在个人私有项目资料中。
- **尚未完成全字段订单级重建。** 整合账本未为每行保留交易所唯一订单/成交 ID；部分行缺少完整时间及合约市场标签。因此不能按“时间＋金额＋操作类型”盲目去重，也不能据此推导胜率、资产净收益榜、AI 预测优势或逐笔实际滑点。
- 部分「退还」是未成交、部分成交或已撤销余额返还的可能表现，不代表盈利。划转从来不是已实现交易收益；风险会计应把资金流、持仓状态、成交回报、手续费及结算严格分离。
- **适用边界：** 数据属于事件合约场景，不能据此证明本项目已有现货实盘闭环可用，更不能直接迁移风控阈值或触发真实下单。

### E2. 对已冻结 v1.0 的验收补强（已有能力的测试证据，非新增功能）

| 编号 | 归属 | 基于账本发现的验收要求 | 结论 / 状态 |
|---|---|---|---|

| `AUD-LEDGER-02` | C/H · 资金对账 | 买入/退款/卖出/结算独立于转入/转出计算；交易净现金流、资金划转与余额变化满足明确等式，差额标注期初余额及未结权益前提 | **账本金额已核对，应用内测试未执行** |

## 当前决定

优先完成现货与永续的基础交易闭环、AI 可用性、确定性风控和成本后策略验证。保留现有通知、Brain、G1/G2 和研究能力。24小时翻倍挑战仅在完成依赖检查后移除。Polymarket、多角色 AI 和其他高级功能进入后续决策池。
