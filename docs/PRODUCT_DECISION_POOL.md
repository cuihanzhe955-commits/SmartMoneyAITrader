# Smart Money AI Trader · 产品决策池

> 创建日期：2026-11-04  
> 性质：**新想法的候选记录，不代表已批准纳入当前开发任务**  
> 依据：`Smart Money AI Trader v1.0 Stable 最终实施计划书`（2026-11-03，尤其第 3、6、8、11、12 章）。以开发者本机最新源码和实际验收结果为工程事实；公开 GitHub C1 检查点不代表全部本地进度。

## 核心约定

1. **v1.0 先把已经承诺的功能做完，并完成真实执行与安全验收。** 暂不把商业销售、定价、营销或新的“赚钱功能”纳入当前开发范围。
2. **原计划书第 D 阶段本来就包含开源组件 POC。** CCXT、TA-Lib、Pydantic AI、Lightweight Charts 应按原计划审计和验证；不是今天新增加的需求，也不意味着每个都必须采用。
3. **原计划 H 阶段本来就包含策略分析和 AI 决策回放，F 阶段包含 Brain 和记忆与独立评估，G 阶段包含挑战与通知。** 可以选择第三方库帮助实现，但不能因此增加 v1.0 的功能承诺。
4. **新模块先记录、比较，再决定是否引入。** 不修改当前策略、AI 提案、风控、订单状态机、资金账本、`requirements.txt` 或实盘配置；不越过 C 阶段验收门槛。
5. **盈利是研究目标，不是已证明结果。** 回测和 Mock 通过只证明相应工程性质，不等于实盘可靠、策略正期望或 AI 增量收益。
6. **兼容与许可是基本工程要求，不代表现在要商业化。** 新依赖应核查 Windows / Python 版本、维护状态、许可证、供应链、NOTICE、锁版及回滚方式。

## D. 候选进入正式实施时的验收清单

- 先核对是否属于原 v1.0 范围，以及现有代码是否足以完成；不能为了新增库而新增功能。
- 记录明确的版本、许可证、维护情况、依赖体积、Windows/Python 兼容性及分发条件。
- 在隔离环境做最小 POC；与原实现对照，必要时补基准数据和回归测试。
- 涉及交易指标、风险或订单时，必须验证行为差异，并且不允许悄悄改变实盘参数、订单状态或账户数据。
- 为每项候选留下“采用 / 不采用 / 延后”的原因、测试证据与可执行回滚步骤。
- 若声称更有盈利优势，需有净费用、基准、样本外、稳定性和风险指标证据；不能只展示最好的历史曲线。

## E. 私有真实订单账本驱动的审计样本与候选改进（2026-11-04）

> **案例编号：`CASE-GATE-LEDGER-20261102-03`。** 已将一组真实事件合约资金流水作为**私有离线审计样本**归档，并形成逐类对账报告。公开仓库仅记录脱敏工程结论与决策，不上传用户原始逐笔订单、账户标识、资金流水或个人损益金额。该案例**不是**实盘交易策略验证、预测胜率证明或 Gate 事件合约 API 可用性证明。

### E1. 已核对的数据事实和限制

- 私有样本合并后为 **407 条账单分类记录**：**374 条交易类**（买入、退还、卖出、结算）和 **33 条账户划转**。存在不同账单分页重叠，整合过程中已按来源排除已知重复片段。
- 已按原始金额正负号核算交易现金流，并用划转和条件性理论期末余额进行**独立的会计等式核对**；完整精确金额、日期范围、Excel 原件、哈希与核对口径放在个人私有项目资料中。
- **尚未完成全字段订单级重建。** 整合账本未为每行保留交易所唯一订单/成交 ID；部分行缺少完整时间及合约市场标签。因此不能按“时间＋金额＋操作类型”盲目去重，也不能据此推导胜率、资产净收益榜、AI 预测优势或逐笔实际滑点。
- 部分「退还」是未成交、部分成交或已撤销余额返还的可能表现，不代表盈利。划转从来不是已实现交易收益；风险会计应把资金流、持仓状态、成交回报、手续费及结算严格分离。
- **适用边界：** 数据属于事件合约场景，不能据此证明本项目已有现货实盘闭环可用，更不能直接迁移风控阈值或触发真实下单。

### E2. 对已冻结 v1.0 的验收补强（已有能力的测试证据，非新增功能）

## 历史决定（截至 2026-11-06）

**继续执行 v1.0 既定 A–I 阶段计划。** 目前优先完成 C · 实盘核心验收；之后 D 阶段照计划评估 CCXT、TA-Lib、Pydantic AI 和 Lightweight Charts；F/G/H 按原计划实现 Brain、挑战、通知和分析。除计划原有验收内容外，本池研究候选**暂不纳入当前开发任务、不安装、不影响实盘**。

如需调整任何一项状态，应先由用户明确决定，并更新本文件和对应阶段记录。


## 当前决定（2026-11-11，优先执行）

1. 当前唯一交付主线是 [v0.1 范围合同](V0_1_SCOPE_CONTRACT.md)：单一已核验现货数据源、1–3 个交易对、一套现有规则策略、纸面交易、成本后盈亏、暂停/停止/重启恢复。
2. v0.1 AI 默认关闭，仅可选解释/复盘，不参与下单。
3. UI 主导航收敛为首页、运行、历史、设置；其他功能隐藏/下沉，不删除代码、数据、API、数据库表、测试和历史报告。
4. v0.1 暂不开放实盘、永续执行、事件合约、新交易所、新通知渠道、新 Agent 和新挑战玩法；这些是阶段性后置，不是 v1.0 永久取消。
5. v1.0 最终目标仍保留现货与永续、模拟与真实交易；真实交易需独立安全验收和明确授权。
6. 24 小时翻倍挑战已获准移除，不再进入决策池；先审计路由、配置、调度、数据库、测试、报告和打包依赖，再只删除挑战专属代码与入口，保留历史报告/记录。G1 自动预测挑战、Brain、通知、策略实验室和通用回测必须保留。
7. 一个活跃写入者、一个任务分支、一个功能 PR；CI 失败不得通过删测试或手改审计结论绕过。
8. 每项新功能先检查当前仓库和 GitHub 开源实现，评估许可证、维护状态、兼容性、安全和回滚后再决定自研或复用。
