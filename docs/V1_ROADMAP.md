# Smart Money AI Trader · v1.0 公开开发路线图

> 公开摘要日期：2026-11-04  
> 本文整理既定 v1.0 Stable 阶段目标，**不新增功能范围，不替代具体开发验收记录**。  
> 当前源码已包含 v1.0 F4成本研究检查点，**不是 Stable 或已完成实盘验收的版本**。

## 产品目标与验收原则

打造可用的本地 AI 辅助量化交易工作台，涵盖规则与 AI 决策、模拟研究、受控真实交易、独立风控、订单状态管理、可视化界面及可追溯结果。盈利能力是研究与评价的重要目标，但软件发布不承诺固定收益或必然获利。

发布功能必须能够从界面到后端状态真实运行；历史模拟、Mock、只读检查、平台模拟环境和真实资金验收须分别标注，不能相互替代。公开状态和历史证据见 [C1 验收记录](PHASE_C1_RESULTS.md) 与 [实盘验证状态](LIVE_TRADING_VERIFICATION.md)。

## A–I 九阶段计划

| 阶段 | 既定目标 | 退出依据 |
|---|---|---|
| A · 基线审计 | 审计现有代码、环境、依赖、数据库及恢复能力 | 有可复核的基线、测试与回滚记录 |
| B · 可靠性修复 | AI 调度解耦、决策过期处理、保护性任务、订单幂等与故障恢复 | 关键异常路径与回归测试通过 |
| **C · 实盘核心验收** | 真实现货交易链、成交/撤单/费用/余额对账、自动健康自检、保护措施 | 取得逐项真实验证证据，不能由 Mock 代替 |
| D · 开源组件 | CCXT、TA-Lib、Pydantic AI、Lightweight Charts 最小 POC | 兼容性与许可证审查、采用/不采用理由、可回滚 |
| E · 多交易所 | Gate / OKX / Binance 单主平台切换与能力隔离 | 分平台、分产品验证，不能用一所通过代表全部 |
| F · Brain 与事件研究 | 模拟开始积累可追溯记忆；独立事件预测及模拟研究 | 可信结算、记录可复现、数据与账本隔离 |
| G · 挑战与通知 | 保留纯规则挑战；AI 预测研究挑战；飞书/Telegram 异步通知 | 完整运行、中断恢复、消息去重与失败隔离 |
| H · UI 与研究分析 | 设置中心、模型与通道配置、AI 决策回放、策略分析、用户操作体验 | 用户操作闭环、可追溯统计和多分辨率检查 |
| I · Stable 验收 | 全量回归、安装启动、数据库迁移、安全、依赖复核、实盘证据 | 无阻断缺陷且有对应验证证据；否则仍为候选版 |

**当前状态：D 组件验收完成，E 非资金实现与本地验收完成；完整 E 平台门槛与 C 实际账户/资金验收仍未通过。** D 的实际证据见 [D验收记录](PHASE_D_RESULTS.md)；E 的实际实现及剩余外部门槛见 [E验收记录](PHASE_E_RESULTS.md)；F1–F3已接入只读发现、盘口/基准费率和官方结算证据，见[F记录](PHASE_F_READONLY_RESULTS.md)；受限v1费用/成本研究已实现，见[F4记录](PHASE_F4_COST_RESEARCH.md)；继续核验原生执行单位并建立模拟/Brain闭环。D完成不代表真实资金闭环或全部产品交付。

## D 阶段已明确的 GitHub 组件

- **CCXT：** 沿用已有交易所适配基础，先做接口与规则对照验证。
- **TA-Lib：** 对 RSI、ATR、EMA 等指标开展预热、缺失值、数值结果及 Windows 兼容 POC，验证前不替换生产指标。
- **Pydantic AI：** 条件引入；现有结构化 AI 通道已满足要求时可以不采用。
- **Lightweight Charts：** 复用已安装的前端依赖，完善信号、行情、历史回放及主题表现。
- **Freqtrade、Hummingbot、Jesse：** 以设计与测试方法研究为主，不直接迁移整套外部系统。

任何模块进入程序前，应记录版本、许可证、依赖与供应链风险、隔离测试及撤销方法。**研究第三方代码不等于自动同意集成。**

## 已在 v1.0 范围内的研究验收

v1.0 的策略与 AI 研究并非空白：既有计划包含模拟交易经验记录、可解释决策、历史回放、绩效统计，以及 Brain 的有/无记忆对照和防止未来数据泄漏的检验。评估包括净收益、回撤、预测概率校准等适用指标。

这些是**原定能力和评估方向**，不能因为建立未来候选池而擅自删除；但它们也不意味着已经证明策略具备长期正期望。更复杂的自动优化、独立大数据基础设施、机器学习预测或多智能体平台，应先在 [产品决策池](PRODUCT_DECISION_POOL.md) 评审。

## 版本控制与用户可见状态

1. 原定 v1.0 范围优先，新增想法不直接进入当前实施阶段。
2. **已规划 / 已实现 / 离线测试通过 / 平台联调通过 / 真实账户验收通过** 必须有明确区分。
3. 任何策略、风控、交易权限或账户绑定的改动，都需要独立测试与明确授权。
4. 不把商业化、定价或销售作为当前 v1.0 交付任务。
5. 公开文档只披露产品设计、可复核技术事实和安全的操作说明，不包含私人配置、密钥或内部协作细节。
