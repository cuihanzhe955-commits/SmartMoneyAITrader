本报告覆盖当前最新 `main` 检查点 `40885c540e6c5f2b69198160cb630c246e318846`。此前
`COMPONENT_DECISIONS.md` 中的“保留、条件引入、研究参考”只作为历史记录，不再视为采用
批准；本报告的实测结果优先。测试在临时 Python 3.12 环境执行，没有修改生产依赖清单、

当前没有发现可以直接替换整个交易运行时的候选。可复用的成熟成果应拆成边界明确的

## 基线失败

在临时 Linux 环境运行现有组件与指标回归：

```text
43 passed, 1 failed
```

失败测试为 `test_research_api_does_not_create_or_modify_trading_session`，导入
`terminal.settings` 时缺少 Windows 专属 `win32crypt`。这证明当前测试入口不能在 Linux
直接代表 Windows 产品可用；同时也说明依赖清单中的 `pywin32==312` 不能作为跨平台开发
环境的通用安装方案。该失败不是候选模块导致的。

## 只做静态适配审查的成熟项目

- **Freqtrade**：成熟度和测试规模高，但 GPL-3.0，且会引入第二套策略、执行器和账本；
  只借鉴订单/回测测试方法，不复制代码或接管当前运行时。
- **Hummingbot**：Apache-2.0，但执行器和连接器范围过大；当前没有证明接入它能解决
  SQLite 恢复或 v0.1 纸面闭环，因此暂不安装。
- **Jesse**：MIT，研究和回测设计有参考价值；未证明其数据模型能无损映射本项目的
  成本、滑点、订单身份和恢复记录，因此暂不替换现有账本。
