# PR #1 与全仓只读审查问题台账

## 结论

PR #1 当时存在至少一项 P1 阻断问题、两项 P2 逻辑或验收问题，以及若干需要补充证据的风险。审查基于源码、差异、历史报告和测试代码的只读核查，未执行本轮 Windows 测试、浏览器测试、真实 API 或数据库迁移。

## 需要跟踪的问题

### PR1-001 · P1：早于预测的官方结果可能使轮次长期等待

结算逻辑拒绝 `resolved_at <= decision_at` 的结果，但等待状态只延迟后重试，未定义确定性无效结果的终态。需要区分暂时接口故障与永久无效结算，并通过可追踪的撤销/退款保持参考账本、现金和对账一致；停止和重启后不得继续重复请求。

### PR1-002 · P2：大量旧暂停记录可能阻塞新轮次

调度查询包含暂停记录并限制扫描数量，50 条以上旧记录可能使新的活动轮次长期得不到处理。应按可调度状态和时间公平选取，并增加大量历史暂停记录下的调度测试。

### PR1-003 · P2：完整进程重启和旧数据迁移证据不足

已有测试重建了部分管理对象，但没有证明关闭全部进程后重新打开同一 SQLite 文件，能够覆盖 RESERVED、QUEUED、FETCHING、PREDICTING、WAITING、SETTLED、STOPPING 状态且不重复扣费、结算或排队。应使用隔离历史数据补充完整重启矩阵。

### PR1-004 · P2：停止时后台线程关闭顺序需要验证

后台工作线程使用有限等待后关闭外部资源。应注入可释放的卡住请求，验证停止、重开和中断期间不会迟到写入、重复调度或访问已关闭连接。

### PR1-005 · P3：统计和回撤口径需要补充边界测试

预测、参与、完成、准确率和成本基础回撤的定义不同于真实市场净值。应覆盖未结算资金、部分成交、非二元结果、概率 0.5、早结果、人工终止和恢复，并在界面和导出中明确这是模拟参考结果。

### PR1-006 · P2：缺少针对当前提交的自动化门禁

历史测试报告不能替代针对最新提交的独立回归。应保留隔离 Python 回归、前端构建、数据库恢复、打包检查和适用的浏览器检查，并记录实际提交号和未执行项目。

## 全仓验收边界

- 真实账户、真实资金、平台成交、费用、余额、保护和退出对账仍未通过验收。
- 本地 API 的回环边界、Host/Origin、跨站请求和意外局域网暴露需要专门安全验证。
- 非资金模拟、公开只读行情和测试替身不能证明外部市场完整可用，也不能证明真实模型质量或策略收益。
- 通知 Outbox、Worker、Gateway、事件研究、Brain、永续连接器和历史实验代码继续保留，但各自证据不能互相替代。
- 当前文档中的测试数量均应视为对应检查点的历史证据，不能自动继承到新提交。
