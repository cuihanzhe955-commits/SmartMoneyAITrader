# 开发协作规范

本文规定 SmartMoneyAITrader 的分支、交接、测试和发布要求，适用于所有参与项目的开发者。

## 1. 基本原则

1. `main` 是受保护的共享基线，不直接在其上开发。
2. 一个任务只允许一个活跃写入者和一个专用分支。
3. 计划书定义范围，进度文档记录状态，源码和测试证据决定实际完成度。
4. 每项变更通过拉取请求审查后再合并。
5. 模拟、回放和 Mock 不能替代平台演示或真实资金验收。

## 2. 开始任务前

开始前必须确认：

- 当前 `main` 的提交号和工作区状态；
- README、主计划、进度文档及任务相关报告；
- 现有实现、调用方、测试、配置、数据库结构和打包清单；
- 未合并的拉取请求及可能冲突的工作分支。

任务说明应写明目标、允许修改的路径、禁止修改的范围、验收标准和测试命令。发现基线或范围发生变化时，先重新评估，不覆盖已有工作。

## 3. 分支、提交与交接

- 分支只处理一个可审查的任务，不混入无关重构。
- 禁止直接提交到 `main`、强制推送或改写共享历史。
- 交接时记录基线提交号、当前提交号、已完成和未完成事项、修改文件、测试证据及已知风险。
- 文档维护、功能开发和实验性工作使用清晰、可检索的分支名称。

## 4. 测试与合并

测试报告必须注明环境、提交号、测试命令、通过/失败/跳过数量，以及未执行测试的原因。涉及前端、Windows 启动器、数据库、交易状态或通知链路时，必须执行对应的定向检查。

合并前应满足：

- 与变更相关的必需测试通过；
- 没有未解释的失败；
- 安全、数据边界和兼容性检查通过；
- 进度文档和使用说明已同步。

## 5. 安全与交易边界

- 不提交密钥、令牌、私钥、真实账户数据或个人信息。
- 默认使用合成数据、历史数据和隔离模拟环境。
- 未经单独批准，不连接真实账户、不创建真实订单、不执行资金操作。
- 不绕过交易所资格、风控、订单状态或恢复流程。
- 收益、胜率和回测结果必须标注数据来源、样本范围、成本假设和局限。

## 6. 交付内容

每个拉取请求应说明变更目的、文件范围、测试结果、未解决问题和回滚方式。合并后及时删除已完成的临时分支和工作树，但保留源码、测试、数据迁移历史和仍有参考价值的验收记录。
