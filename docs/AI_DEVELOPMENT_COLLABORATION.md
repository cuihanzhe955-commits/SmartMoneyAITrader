# AI 协作开发规范（含历史 Codex/Copilot 分工）
> **当前执行安排（2026-11-11）：** 下一轮由 GitHub Copilot 作为唯一活跃写入者。Codex 当前不参与本轮开发；其他 AI 不得并行修改同一工作区。项目所有者负责确认范围、批准依赖/删除/迁移和最终合并。以下原有角色、额度和交接规则保留为历史参考；与本段冲突时以本段为准。


> 适用项目：Smart Money AI Trader  
> 文档建立日期：2026-11-06  
> 建立时 main 基线：`2d55453a658f85172e975d8c1d37b89196402f16`  
> 本文是仓库协作流程规范，不改变 `SmartMoney_Stable_Plan.md` 的产品范围、架构决策或阶段验收门槛。

## 1. 目标与基本原则

在 OpenAI Codex 使用额度暂时耗尽、需要切换到 GitHub Copilot Student 时，保证开发能够连续进行，同时避免两个 AI 对同一文件并发修改、互相覆盖或引入未经审查的架构变化。

必须遵守：

1. **GitHub main 是共享基线，不是 AI 的直接工作区。** 所有 AI 开发都从最新 main 创建独立分支。
2. **一个任务、一个写入者、一个工作分支。** 不同 AI 不得同时写同一分支或同一工作树；本轮仅 GitHub Copilot 是活跃写入者。
3. **计划书定义要做什么，进度文档定义当前状态，源码和测试证据定义实际上做到了什么。**
4. **Pull Request 是交接与审查边界。** 默认先提交 PR，人工审核后再合并。
5. **不以测试数量代替平台验收。** Mock、历史回放、公开只读数据和模拟账本不得冒充 demo 或真实资金验收。

## 2. 两个 AI 的职责

### Codex：历史主开发职责（本轮不启用）

优先承担：

- 复杂架构设计、跨模块任务拆分和技术方案比较；
- 核心交易生命周期、风险边界、状态机、账本和恢复逻辑；
- 涉及多个模块的集成实现；
- 复杂故障定位、全量回归和阶段验收报告；
- 审查 Copilot 的改动是否符合主计划和系统架构。

Codex 额度不足时，必须留下可交接的 Git commit、任务说明、已完成/未完成清单和测试证据；不能只留下聊天摘要。

### GitHub Copilot Student：本轮唯一活跃开发者

优先承担：

- 明确范围内的小型功能实现和缺陷修复；
- 单元测试、回归测试、边界条件和错误处理补充；
- 代码解释、静态检查、重构建议和 PR 审查；
- README、阶段文档、使用说明和变更记录同步；
- 在 Codex 暂不可用时，接续已明确拆分且验收条件清楚的任务。

**额度与功能边界：** 当前 Student Developer Pack 页面说明 Copilot Student 包含无限代码补全、一定额度的 GitHub AI Credits，以及有限的 Chat/Agent 使用；模型由自动选择，不保证可手动固定某个模型。IDE 内 Agent Mode 与 GitHub Copilot Cloud Agent 是不同能力；不得假定 Student 权益包含付费计划的 Cloud Agent。使用前应在 GitHub 当前计划页面核对账号实际显示的功能和额度。

### 项目所有者：最终决策人

只有项目所有者可以批准：

- 产品范围、架构和主计划变更；
- 新增或升级生产依赖；
- 数据库迁移、数据格式变更和删除操作；
- 真实平台接入、凭据使用、真实账户操作；
- PR 合并和 Stable 发布。

AI 可以提出方案，但不得自行扩大授权范围。

## 3. 每次任务开始前的必读与核对

每个 AI 在开始写代码前必须：

1. 拉取最新 `main`，确认当前 commit SHA 和工作区干净状态。
2. 阅读：
   - `README.md`
   - `docs/SmartMoney_Stable_Plan.md`
   - `docs/PROGRESS_STATUS.md`
   - `SOURCE_MANIFEST.json`
   - 与本任务直接相关的阶段报告和设计文档。
3. 检查已有实现、调用方、测试、配置、数据库结构和打包白名单，避免重复开发或遗漏隐式依赖。
4. 输出任务范围：目标、允许修改的文件/目录、明确不修改的部分、验收标准和测试命令。
5. 先检查是否存在未合并 PR、其他 AI 的活跃分支或相同文件的未完成改动。

若 main 已变化、目标文件已有其他未合并修改，先重新评估，不得覆盖他人工作。

## 4. 分支与交接规则

建议命名：

- Codex：`ai/codex/<issue-id>-<short-topic>`
- Copilot：`ai/copilot/<issue-id>-<short-topic>`
- 纯文档维护：`docs/<short-topic>`

规则：

- 禁止 AI 直接提交到 `main`；禁止 force-push；禁止重写共享分支历史。
- 每个分支只处理一个可审查任务，避免把无关重构混入 PR。
- 同一任务由 Codex 切换给 Copilot 时，原写入者先停止编辑并提交/推送当前进度；交接说明必须标明最后 commit SHA、已修改文件、测试结果、未解决问题。
- 接手者从该 commit 创建自己的续接分支，或在明确批准后接管原分支；不得让两个 AI 同时写入。
- 若 Copilot 仅做审查，要求它只给出 findings 和建议，不直接改文件；若需要修复，另开分支。
- 合并前先更新目标分支并解决冲突，再重新运行受影响测试。最终由项目所有者审核并合并。

## 5. 任务交付合同

每个 AI 的任务说明必须包含：

- 任务 ID 与当前基线 SHA；
- 目标和不在范围内的事项；
- 允许修改的路径；
- 不可触碰的路径；
- 行为约束和兼容性要求；
- 验收标准；
- 必须执行的测试命令。

交付时必须提供：

1. 修改文件清单和每个文件的目的；
2. 关键实现与设计取舍；
3. 实际执行的命令、运行环境和完整测试摘要；
4. 通过/失败/跳过数量，不能只写“测试通过”；
5. 未执行的测试及原因；
6. 风险、限制、未解决问题；
7. 文档同步情况；
8. commit SHA 和 PR 链接。

不得伪造测试输出，不得将计划实现写成已实现，也不得把局部测试数量描述为全量回归结果。

## 6. 测试与质量门槛

按任务影响范围执行，至少考虑：

- Python 定向测试和隔离全量回归；
- TypeScript 类型检查；
- 前端生产构建；
- Playwright 浏览器测试（适用时）；
- 状态恢复、重复请求、超时、取消、迟到响应和异常输入测试；
- 依赖与许可证审查（修改依赖时）；
- 数据库迁移和旧数据兼容测试（修改 schema 时）；
- Windows 目标环境验证（涉及启动器、安装器、路径或系统 API 时）。

测试报告必须注明：本地/云端环境、操作系统、Python/Node 版本、使用真实平台还是 Mock/历史数据、测试执行时间和 commit SHA。

**合并门槛：** 所有与改动相关的必需测试通过；没有未解释的失败；安全与数据边界检查通过；文档和进度状态同步；项目所有者批准。

## 7. 安全、凭据与交易边界

- 不得将 `.env`、API Key、Secret、私钥、助记词、Cookie、访问令牌或真实账户凭据提交到 Git。
- 不得把真实交易账单、个人身份信息、账户余额或本地数据库上传到 Copilot、Codex Cloud、Camber、Deepnote 等第三方服务；确需分析时先由项目所有者脱敏并确认数据范围。
- 公开仓库只允许提交适合公开披露的源码、测试夹具和文档。当前仓库为 Public，所有提交内容都应按公开内容审查。
- 默认使用合成数据、历史数据、Mock 和隔离模拟环境；不得连接真实账户、创建真实订单或执行真实资金测试。
- 不得绕过交易所地区限制、产品资格限制或 API 能力限制。
- AI 产生的预测、收益、胜率和回测结果必须标注数据来源、样本范围、费用假设和局限，不得宣传收益保证。
- 不得擅自删除用户数据、重置数据库、覆盖备份或修改生产配置。

## 8. Codex 用量耗尽时的标准接力流程

1. Codex 停止新写入，整理当前任务状态。
2. 确认所有有效改动已提交到专用分支并推送；未提交的本地改动不会自动出现在 GitHub 或云端环境。
3. 写出交接摘要：基线 SHA、最新 commit SHA、已完成事项、剩余任务、受影响文件、测试命令与结果。
4. 在 VS Code 中使用已激活的 Copilot Student，登录同一 GitHub 学生账号。
5. Copilot 从指定 commit 创建独立分支，只接手明确的剩余任务。
6. Copilot 完成后提交 PR，不直接合并。
7. Codex 额度恢复后，可由 Codex 审查 PR 或继续集成；审查与修复必须分开提交。
8. 所有变更合并后，回到 Windows 本地工程同步最新 main，再执行目标 Windows 环境回归。
