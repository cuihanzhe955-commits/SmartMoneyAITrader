## 6. 下一步唯一开发优先级：S0 稳定性收尾

先在独立分支从当前确认的 main 创建工作区，逐项复现第2节四个问题，提出根因和最小修复，再实施与回归。不得同时开展大规模 UI 重构、多 Agent 重构或策略参数优化。

S0 验收至少包括：
- 每项已知问题有可复现步骤、根因证据、修复差异和回归用例；
- 受影响定向测试、完整离线回归、前端构建、浏览器/压力测试及 Windows 启停检查；
- 无未解释的 ConnectionResetError、工作线程意外退出、资源泄漏或残留进程；
- 退出码为 0 但日志仍含未解释异常时，仍判定未通过；
- 输出修改文件、原始命令和测试结果、回滚点、剩余风险。

S0 通过并经独立复审后，再进入 UI 双模式和 AI 团队正式实现。AI 实时路径必须采用并行、截止时间与部分结果策略，不能要求所有角色串行完成。

## 7. 产品升级方向（已确认，尚未实现）

1. UI：新手模式与专业模式共存，共用同一后端、交易引擎和风险控制。
2. AI：市场分析师、策略研究员、AI 交易员、AI 风险顾问、Brain 五角色；不要求一角色一模型。
3. 提案新鲜度：时间、价格偏移、波动率、流动性、快照序列、持仓/账户/配置版本多维检查；采用 proposal generation / fencing token 隔离迟到结果；执行器入口再次校验。
4. AI 调度：并行、截止时间、有界队列、部分结果；研究员和 Brain 深度学习工作异步运行，不阻塞保护与对账。
5. 盈利目标：稳健策略为主，高收益策略独立研究；使用规则、AI、AI+Brain 三组配对测试，成本后样本外和前向结果为准，不承诺盈利。
