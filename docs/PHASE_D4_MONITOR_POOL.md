# D4 候选池与必须监控集合隔离

日期：2026-11-04。开始前本地基线 `0033828`；fetch 后远端 main 仍为 `bc51b68`。本轮修改运行时监控边界，未开启动态新币自动交易、未扩大真实账户授权。

## 实际修改

- `market/pool.py`：区分入场候选与必须监控集合。持仓和在途委托优先去重并保留，即使候选落选或位于黑名单也不丢弃；无效币种标识明确报错。提供 D3 研究报告转换适配器：错平台、未来/过期/缺失时间的结果不能准入，仍保留原仓/原单监控。转换器不授予执行权限。
- `execution/venue.py`：行情读取接受显式监控集合，先请求必须监控币种，随后请求普通候选。普通候选请求失败记录原因并保留已取得数据；限频立即停止后续候选请求，不自动重试。必须监控交易对缺失、超时或没有收盘线时明确失败，不用旧价格冒充有效数据。地区或权限拒绝仍向上阻断，不作为可忽略候选错误。
- `terminal/runtime.py`：实时会话每次扫描从持久化持仓、模拟在途单和当前交易所待核对单重新构建监控计划。额外监控参数只传给本次行情读取，不写入用户策略配置。保存候选数量、必须/计划监控数量、取得及通过校验数量、错误原因、最近尝试时间。沿用原订单与保护独立调度通道。
- `challenge/manager.py`：接收明确入场集合。只有合格入场候选消耗排名名额；额外保留的持仓照常执行已有退出条件。模拟买单退出候选池时在撮合前取消；交易所未知订单不因候选变化被删除或盲目撤单。历史/CSV 未提供入场集合时保留原行为。
- `frontend/src/main.tsx`：市场雷达显示上述真实运行状态、保留监控原因及失败原因，并明确动态研究结果尚未自动用于开仓。
- 新增 `tests/test_monitor_pool.py`、`tests/pool_browser.py`，更新证据、清单与版本信息。

## 边界与剩余工作

当前开仓数据池仍为原固定8币；本轮先把保留监控与准入边界接进实际 Runtime，不宣称已开启动态自动交易。D3 报告适配器通过测试，但尚未自动连接为生产准入源。

行情收盘线读取仍为同步序列：本轮隔离了候选失败后的数据结果，但尚未消除慢候选请求的等待时间。实时交易所原有独立保护线程保留；模拟扫描的异步行情调度、候选数据缓存/限额及完整策略规则接入仍是后续工作，不能据此宣称所有保护路径均不受慢行情影响。

D 阶段仍有图表压力/完整回放和全依赖供应链复审；E 的动态准入与多平台切换尚未整体验收。C 真实账户/资金验收依用户决定后移，仍是 Stable 门槛。
