# F5.1 事件研究记录基础

日期：2026-11-06。基线：`3493218`。这是F阶段的研究记录增量，不是完整事件模拟账本或Brain交付。

## 已实现

- 在同一`runtime/terminal.db`中逻辑隔离`event_research_observations`，只在首次成功保存时增量建表；启动、查询不迁移已有交易表。原现货会话、订单、成交、持仓不修改。
- UI在成本结果中提供「保存研究记录」，在策略实验室提供历史列表与证据查看。保存时后端重新调用受限成本服务，保留实际保存的结果，价格可能与先前显示不同。
- 记录平台、产品、research环境、输入参数、行情源时间/哈希、成本和未验证条件、保存时间、Schema版本、内容SHA256。校验值用于检测意外数据损坏，不是签名或防恶意篡改证明。
- 客户端只提交查询参数和请求ID，不能上传自编快照或执行权限。同一请求重试返回原记录；重启后仍可识别，不重新抓取当前价格覆盖历史。相同ID改参数会拒绝。
- 并发重试在短SQLite事务中只提交一条；网络读取不在事务内，也不持有Runtime锁。数据库忙100ms后明确失败，可用同一请求重试；失败事务回滚，不记录部分成功。
- 过期、未来时间、错误平台/产品/市场或异常权限快照拒绝保存；校验失败保留原数据并提示，不静默修复或纳入学习。

## 操作

策略实验室 → 查询Polymarket公开市场 → 查询公开详情 → 选择结果 → 计算公开盘口成本 → 保存研究记录。下方「已保存的事件研究记录」显示最近20条，可刷新、查看完整证据；重新打开软件后仍可读取。保存失败后可直接重试。改参数后先重新计算再保存。

记录是历史研究证据，不产生资金冻结、订单ID、模拟/真实成交、已实现收益或验证后经验。原生CLOB单位、实际抵押资产与扣费仍未验收，不能靠保存记录开启执行。
