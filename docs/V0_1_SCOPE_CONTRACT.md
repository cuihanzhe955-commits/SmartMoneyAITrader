# SmartMoneyAITrader v0.1 范围合同

> 版本：2026-11-11。当前唯一交付里程碑；不替代 v1.0 完整产品目标。  
> 权威依据：[主实施计划 §16.12–§16.13](SmartMoney_Stable_Plan.md)、[产品审计记录](PRODUCT_AUDIT_20261111.md)。

## 1. 目标

交付一个普通用户能在干净 Windows 环境安装、启动、理解、运行、停止、重启恢复，并查看成本后纸面交易结果的最小量化交易工作台。

## 2. 纳入范围

- 一个经本机只读核验确认可稳定获取公开现货行情的交易所。
- 1–3 个数据完整、规则可核验的现货交易对；具体选择不得在本机审计前预先指定。
- 一套已有规则策略，优先复用当前实现。
- 纸面交易和可复核模拟撮合。
- 明确计算手续费、滑点、最小交易单位、净值和回撤。
- 交易流水、运行状态、错误信息、暂停/停止和重启恢复。
- 可选 AI 中文解释/复盘；默认关闭，不提交订单，不改变规则信号，不绕过风控。
- 四个主导航：首页、运行、历史、设置。
- 干净 Windows 安装、启动、停止和基本恢复验证。

## 3. 明确不纳入 v0.1

真实资金下单、永续执行、事件合约执行、新交易所、新通知渠道、新 AI Agent/多角色团队、新挑战玩法和新主导航页面。

这些限制只针对 v0.1，不表示 v1.0 永久取消现货/永续、模拟/真实交易能力。v1.0 最终方向仍保留现货与永续，以及完成单独安全验收后开放真实交易的目标。

## 4. 最大程度保留既有成果

默认保留现有 Python/FastAPI、React/TypeScript、SQLite、CCXT、规则策略、风险、订单状态、恢复、AI Provider、Brain、通知 Outbox/Worker/Gateway、G1/G2、事件研究、策略实验室、回测、实验报告、交易流水、账户/持仓和现有测试。

非 v0.1 主流程功能可从主导航隐藏、移动到实验区或二级入口；不得仅为简化 UI 删除实现、API、数据库表、历史数据、测试、报告或许可证文件。

“24 小时翻倍挑战”已获准退出当前产品范围：先隐藏入口，检查路由、配置、调度器、数据库、测试、报告和打包依赖，再仅删除挑战专属代码。G1 自动预测挑战和通用研究/回测能力不得连带删除。

## 5. UI 验收

- 主导航只突出：首页、运行、历史、设置。
- 中文优先；内部术语移至高级详情。
- 关键数据标明来源、时间、模拟/真实环境和成本口径。
- 状态、错误、暂停、停止和恢复结果必须可见。
- 其他研究/实验模块保留但不抢占主流程。

## 6. 垂直切片验收清单

- [ ] 干净 Windows 目录安装并启动，不依赖开发者已有虚拟环境或数据库。
- [ ] 用户能创建默认纸面会话。
- [ ] 行情来源、交易对、时间戳、缺失/过期数据处理可见。
- [ ] 规则策略能产生可解释信号；无信号时明确显示观望/跳过。
- [ ] 模拟订单按明确规则撮合；不使用未来数据。
- [ ] 手续费、滑点、数量精度和最小订单金额纳入计算。
- [ ] 订单、成交、持仓、现金、净值、盈亏和回撤可对账。
- [ ] 暂停/停止不会丢失未完成状态；重启后恢复或明确要求人工核对。
- [ ] 能导出交易记录和净值结果。
- [ ] AI 默认关闭；开启后仅解释/复盘，显示模型、延迟、费用和失败原因。
- [ ] Python 定向与全量离线测试通过。
- [ ] 前端类型检查和生产构建通过。
- [ ] 浏览器关键流程通过；日志无未解释异常。
- [ ] Windows 启停和干净环境冒烟测试通过。
- [ ] GitHub Actions 必需检查通过；不得绕过失败测试。
- [ ] README、使用说明、进度文档和本合同同步。

## 7. 开发规则

1. 开发前只读审计 GitHub main、本机所有工作树、运行目录、数据库和备份。
2. 不重置、不清理、不覆盖、不迁移任何未知本地文件。
3. 先查现有代码和 GitHub 开源实现；适合时优先复用。
4. 生产依赖、许可证、数据库迁移、模块删除和架构替换必须先评估并获项目所有者批准。
5. 一次只允许一个写入者、一个功能分支、一个 PR；PR 通过目标测试后由项目所有者合并。
6. 不使用真实 API 凭据，不读取真实账户，不提交真实订单，不连接钱包签名或转出资产。
7. Mock、历史回放和模拟成交不得标记为平台联调或真实账户验收。

## 8. 后续版本门槛

v0.1 通过后，再逐项验收永续模拟、现货/永续真实交易准备、AI 固定样本评估、成本后回测、样本外、Walk-forward、前向模拟、通知生产 Runtime/UI 和更多平台。

真实交易必须单独通过权限、订单、成交、费用、保护、资金核对、退出、异常和恢复验收，并取得用户明确授权。
