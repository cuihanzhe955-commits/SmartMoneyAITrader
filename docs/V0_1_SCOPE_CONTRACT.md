# SmartMoneyAITrader v0.1 范围合同

> 版本：2026-11-11，DOC-01 修订。
> **本合同覆盖并取代此前将真实现货、AI 自动决策和生产通知排除在第一版之外的表述。**
> 权威依据：[主实施计划 §16.14](SmartMoney_Stable_Plan.md)、[项目进度](PROGRESS_STATUS.md)和[实盘验证状态](LIVE_TRADING_VERIFICATION.md)。

## 1. 目标

交付一个普通用户能在干净 Windows 环境安装、启动、理解、运行、停止、重启恢复，并核对成本后结果的第一版量化交易工作台。第一版同时包含纸面交易闭环和真实现货自动交易闭环；真实交易默认关闭，只有通过五项强制实盘门槛并获得明确授权后才能启用。

## 2. 纳入范围

- 一个经本机只读核验确认可稳定获取公开现货行情的交易所。
- 1–3 个数据完整、规则可核验的现货交易对；具体选择不得在本机审计前预先指定。
- 一套已有规则策略，优先复用当前实现。
- 纸面交易和可复核模拟撮合。
- 真实现货自动交易：规则或 AI 决策经独立风控后进入真实订单链。
- 明确计算手续费、滑点、最小交易单位、净值和回撤。
- 交易流水、运行状态、错误信息、暂停/停止和重启恢复。
- AI 自动决策、AI Provider、策略选择和 Brain；默认安全关闭或处于观察/模拟状态，未通过对应验收不得进入真实订单。
- OpenClaw、飞书和 Telegram 的完整生产通知链路；通知失败不得阻塞交易、保护或对账。
- 四个主导航：首页、自动交易、历史、设置。
- 干净 Windows 安装、启动、停止和基本恢复验证。

## 3. 第一版启用边界

真实现货自动交易纳入第一版目标，但不是无条件开放功能。以下五项必须分别通过，缺一不可：

1. **平台门槛**：目标交易所的行情、账户权限、下单、撤单、查单、部分成交、精度、费率和地区/产品资格逐项验证。
2. **资金门槛**：专用或明确隔离的账户范围、余额、持仓、预算、费用币种和资金变动可在下单前后核对。
3. **保护门槛**：保护单或可验证的退出方案、触发/撤销/部分成交/重启状态已通过平台或等效受控环境验收；本地监控不得冒充交易所托管保护。
4. **对账门槛**：订单、成交、费用、余额、持仓、现金流、净值和异常差异可按唯一身份幂等核对。
5. **恢复门槛**：超时、断线、未知订单、进程停止和重启后能恢复或暂停并要求人工核对，不得重复下单或丢失保护任务。

未通过五项门槛时，真实现货入口必须保持关闭或明确阻断；不得使用 Mock、历史回放、公开只读行情、模拟成交或离线测试替代真实资金验收。永续、事件合约和新增交易所不因本次合同调整自动获得第一版真实交易授权，仍按独立范围和验收决定。

## 3.1 AI、策略、Brain 与通知边界

- AI 自动决策、Provider、策略选择和 Brain 属于第一版能力范围；它们必须有真实状态、超时/失败/费用记录、确定性风控和可追溯决策记录。
- AI 不承诺盈利，不得绕过风控、保护、订单状态或五项实盘门槛。AI/Brain 的 Mock、离线测试和模拟收益不得描述为真实交易结果。
- OpenClaw、飞书和 Telegram 生产通知链路属于第一版能力范围；当前已有 Outbox/Worker/Gateway 的局部或测试证据不等于生产连接、认证、发送和送达验收已通过。
- 通知链路必须异步、有界、可重试、可恢复；通知失败、超时或通道不可用不得阻塞交易核心、保护和资金对账。

## 4. 最大程度保留既有成果

默认保留现有 Python/FastAPI、React/TypeScript、SQLite、CCXT、规则策略、风险、订单状态、恢复、AI Provider、Brain、通知 Outbox/Worker/Gateway、G1/G2、事件研究、策略实验室、回测、实验报告、交易流水、账户/持仓和现有测试。

非 v0.1 主流程功能可从主导航隐藏、移动到实验区或二级入口；不得仅为简化 UI 删除实现、API、数据库表、历史数据、测试、报告或许可证文件。

“24 小时翻倍挑战”已获准移除：审计依赖后只删除挑战专属代码、入口、配置、调度和专属测试，保留历史报告/记录。不得连带删除 G1 自动预测挑战、通用研究/回测、通知或 Brain。

## 5. UI 验收

- 主导航只突出：首页、自动交易、历史、设置。
- 中文优先；内部术语移至高级详情。
- 关键数据标明来源、时间、模拟/真实环境和成本口径。
- 状态、错误、暂停、停止和恢复结果必须可见。
- 其他研究/实验模块保留但不抢占主流程。

## 6. 垂直切片验收清单

- [ ] 干净 Windows 目录安装并启动，不依赖开发者已有虚拟环境或数据库。
- [ ] 用户能创建默认纸面会话，并在通过五项实盘门槛后创建受控真实现货会话。
- [ ] 行情来源、交易对、时间戳、缺失/过期数据处理可见。
- [ ] 规则策略能产生可解释信号；无信号时明确显示观望/跳过。
- [ ] 模拟订单按明确规则撮合；不使用未来数据。
- [ ] 手续费、滑点、数量精度和最小订单金额纳入计算。
- [ ] 订单、成交、持仓、现金、净值、盈亏和回撤可对账。
- [ ] 暂停/停止不会丢失未完成状态；重启后恢复或明确要求人工核对。
- [ ] 能导出交易记录和净值结果。
- [ ] AI Provider、自动决策和 Brain 可配置、可追溯；默认安全关闭或观察/模拟，显示模型、延迟、费用和失败原因。
- [ ] OpenClaw、飞书和 Telegram 生产通知链路可配置、测试、恢复并显示真实状态；通知故障不阻塞交易核心。
- [ ] 平台、资金、保护、对账、恢复五项实盘门槛逐项有证据。
- [ ] Python 定向与全量离线测试通过。
- [ ] 前端类型检查和生产构建通过。
- [ ] 浏览器关键流程通过；日志无未解释异常。
- [ ] Windows 启停和干净环境冒烟测试通过。
- [ ] GitHub Actions 必需检查通过；不得绕过失败测试。
- [ ] README、使用说明、进度文档和本合同同步。

## 7. 开发规则

1. 开发前只读审计 GitHub main、本机所有工作树、运行目录、数据库和备份。
2. 不重置、不清理、不覆盖、不迁移任何未知本地文件。
3. 先查现有代码和 GitHub 开源实现；适合时优先复用。
4. 生产依赖、许可证、数据库迁移、模块删除和架构替换必须先评估并获项目所有者批准。
5. 一次只允许一个写入者、一个功能分支、一个 PR；PR 通过目标测试后由项目所有者合并。
6. 不使用真实 API 凭据，不读取真实账户，不提交真实订单，不连接钱包签名或转出资产。
7. Mock、历史回放和模拟成交不得标记为平台联调或真实账户验收。

## 8. 后续版本门槛

v0.1 通过后，再逐项验收永续模拟、现货/永续真实交易准备、AI 固定样本评估、成本后回测、样本外、Walk-forward、前向模拟、通知生产 Runtime/UI 和更多平台。

真实交易必须单独通过权限、订单、成交、费用、保护、资金核对、退出、异常和恢复验收，并取得用户明确授权。
